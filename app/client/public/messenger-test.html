This page drives raw STOMP directly (it does not import api/stomp.ts), but it mirrors that module's model after the recent changes: a single /user/queue/dm subscription is opened once on connect and kept alive for the whole session, then fanned out to two kinds of listeners — an always-on inbox feed (drives unread badges, like subscribeToDmInbox) and a peer-filtered conversation feed (one open chat, like subscribeToDm).

The DM inbox is subscribed automatically on connect and stays subscribed until you
disconnect — you never have to (re)subscribe per conversation. The Inbox feed below logs
every DM this user receives regardless of which chat is "open"; the Conversation feed
logs only DMs to/from the open peer. Incoming DMs from anyone other than the open peer bump that
peer's unread count — open their conversation to clear it.



  

    

      
      
    

    
  

  

    
    
  

  

    
  


  
  


  
  





4. Server errors (/user/queue/errors)


Subscribed automatically on connect. Rejected requests land here — nothing else reports them,
because STOMP publish has no response and a denied SUBSCRIBE is dropped server-side
(the client's subscribe() call still looks like it succeeded).
